Sequencing is inherited, not chosen here

The spec's reason for building the CLI and MCP last applies with equal force to the mod: "building the CLI/MCP before the API is agent-ready means rewriting both against a moving contract." No mod code should exist before Phase 1 lands snapshot views, events, preflight quotes and idempotency guards. What this document asks for now is only that the Phase 3 client be planned as one core with three heads (§2), so the mod costs little when its turn comes.

1The idea, restated

The spec's endgame is "agents driving scheduled strategies through a CLI + MCP server." The audit describes the finished shape: an agent "enumerates its empire in ~2 RPC round-trips, computes optimal upgrade paths purely off-chain from snapshots, monitors the market via event cursors, and executes a strategy as one retry-safe PTB."

An MCP server delivers tools. It does not deliver a place to watch the empire, a way to shape what the model sees before each turn, or a scheduler that runs without a model. A Claude Code mod delivers all three, in-process, with the same tool code the MCP server uses. That is the whole proposal:

  • A pane beside the transcript: planets, stores against capacity, NOVA, Company prices, build queue, shipments in flight, and — the one that matters most — inbound compliance fleets with a countdown.
  • Shaped context: the compact empire snapshot injected into every turn, so a small model never has to discover state.
  • A free tier: mod code that polls event cursors, evaluates preflight quotes and policy guards, and calls a model only at a genuine fork.

The spec already designs for agent players: "daily check-in + agents" pacing, storage that "pairs with agents that empty storage," upkeep that "suits agent players who budget recurring costs," and an anti-farm model that is dilution, not identity: a fresh planet's emission share is small, so agents are welcome and farms self-limit. The mod is the client that makes that intended play style cheap enough to actually run.

4The three-tier model economy

Agent games get expensive when one strong model reads state, decides and executes on every tick. Split the three jobs by cost. The readiness layer is what makes the middle tier free.

Tier 3 — rare

Strategist

The main session on a strong model. You describe a strategy in words. It compiles that into a policy object — thresholds, priorities, guards, a dodge rule — and stores it.

runs: when you say so · cost: high · once per strategy change
Tier 2 — free

Watcher + executor

Mod code over core. Follows event cursors, refreshes snapshots, evaluates preflight quotes and policy guards, builds and signs PTBs. Calls no model.

runs: on events and timers · cost: zero tokens · most ticks end here
Tier 1 — cheap

Decider

Haiku. Gets the policy and a compact state line. Returns one move. No files, no tools, no history. Used only where the policy says "judgement".

runs: at a genuine fork · cost: low · ~200 tokens per decision

The spec resolves the fairness question this raises. Agents are an intended player type; the anti-farm gate is production-weighted emission plus a level-band interaction rule, not a restriction on automation. The mod does not need to hide that it is an agent, and the game does not need it to.

5The pane

This is the part no other head delivers, and where the revamped game gives it real content. Sketch, not a design:

TRADE WARS · universe 0x77e · overseer Alvaro · NOVA 1,240 · SUI 3.1 planet coords stores (used/cap) build next Homeworld 1:42:7 ER 812/1000 LA 140/600 TH 90/600 lab L2 · 41m LA mine L3 = 200 ER · affordable Colony-A 1:44:3 ER 43/400 LA 900/900 FULL TH — — ship LA out or storage L2 ⚠ INBOUND compliance fleet → Colony-A wants 400 LA arrives in 02:17:40 pays defender rate 1.08× Company · dodge: post offer / ship to Homeworld shipments →Homeworld 300 TH from 0x9c1 · 00:38:12 offers 2 open · 1 filled Company ER 0.42 LA 0.61 TH 1.90 NOVA/unit (LA −8% 1h, re-arming)

Three things on that screen are decisions with a clock on them: a full store halting a mine, an inbound fleet with a dodge window, and an element price that is re-arming toward its anchor. A CLI prints them once. An MCP client sees them only if the model asks. The pane shows them the moment the event lands.

Draw triggers

  • ComplianceLaunched targeting one of my planets → toast, pane alert, and a Tier 1 decision if the policy's dodge rule says "judgement".
  • Store reaches capacity → alert. The spec's halt-at-cap design means this is lost production until acted on.
  • Shipment or fleet arrival_ms passes → redraw, and the free tier files the claim_shipment or execute PTB.
  • Build ready_at passes → claim_build.
  • Timer fallback for reserves, which are clock-computed and drift between events.

8The strategy loop, with real decisions

The revamped economy supplies forks a greedy rule handles badly. That is what justifies a model in the loop at all.

ForkWhy it is a judgement, not arithmeticTier
Sell now or holdThe Company price is an EMA that drops as you sell and re-arms toward its anchor over time. Dumping a lump is worse than pacing; pacing costs time you may not have if a store is near cap.1
Dodge or take the raidSettlement pays the defender at a rate skewed in the defender's favour. Sometimes being raided is the best sale available. Sometimes the element is needed for a build and the dodge window is enough to ship it out.1
Post an offer or raidLane B is cheaper but needs a counterparty; Lane C is a credible fallback that burns fuel on a miss. The spec calls this gunboat diplomacy.1
Where to colonizeFee scales with distance; fuel for every later trade scales with distance too. Clustering versus room.3 — rare, expensive, worth the strong model
Claim, refill, sweep, executeOne correct answer once the clock passes.2 — never a model

The loop

  1. You state a strategy in the main session: "expand to three planets in system 42, rush thorium, pace Company sales to keep LA above 0.5, dodge raids only when the element is earmarked for a build."
  2. Tier 3 compiles it into a policy and calls tw_policy. Once.
  3. You arm autoplay with call and gas budgets.
  4. Tier 2 watches event cursors and clocks. Housekeeping PTBs go out with no model. Guards are checked in code.
  5. At a fork Tier 2 calls Haiku with the policy and the state line, and takes back one move.
  6. Tier 2 executes as one retry-safe PTB, records the receipt, redraws.
  7. You watch the pane. When the strategy stops fitting, back to step 1.

Why the policy is an object

A strategy left in natural language is re-read and re-interpreted on every decision. Compiled to thresholds and guards, most of it is checked by code for free and the model is consulted only for the part that is a judgement. That is the difference between cents per hour and dollars per minute.

9Risks

The mods API is early access

Hook modules load only where function hooks are enabled, and Anthropic's README states the API may change between releases without notice. The mod is an experiment beside the CLI and MCP, never the only client. The core package must not depend on it.

RiskImpactMitigation
Contract driftBuilding against today's 15-call reads means a rewrite at Phase 1No mod code before Phase 1. Inherited from the spec's own sequencing argument.
Key custodyUnattended play needs a signer with no human presentShared with the CLI: one signer interface in core. Testnet and a throwaway key for the experiment. Budgets in tw_autoplay. See §10.
Company write-hotspot (spec R7)At agent scale every mint/burn serializes on shared objectsThe free tier batches housekeeping into one PTB per tick and backs off on conflict. The mod is also a realistic load generator for measuring R7.
Runaway spendA loop that calls a model per second costs money and gasHard call and gas budgets at arming. The tick refuses past either.
Time-dependent readsReserves are clock-computed; a cached value is stale as readCache snapshot inputs, recompute on render. Snapshots return stored and pending split.
A model that does not beat a ruleTier 1 adds cost and no winsMeasure against a greedy baseline at Phase 3 step 4 (§11). If it loses, keep the pane and the tools and drop the agent claim.

10Open questions

  1. Key custody, solved once. The CLI needs the same answer. Options: a local keystore the core reads; a configured sui client profile; or "prepare only" where the mod builds the PTB and you sign. Which is the default for unattended play?
  2. Play while away. $.clock.every lives in a running session. For the spec's daily-check-in pacing, is a Claude Code scheduled routine (cloud) acceptable — which puts the key in the cloud — or does unattended play stay on a local CLI cron and the mod covers only live sessions?
  3. Repo layout. One TypeScript workspace at Phase 3 with core/, cli/, mcp/, claude-mod/? Or does the mod live outside the game repo because its API is early access?
  4. Does the web client migrate onto core? The audit criticised its hand-rolled BCS and 15-call reads. Snapshot views make core a better data layer for it too. In scope for Phase 3 or later?

Resolved by the spec since Rev 1: fairness (agents are an intended player type; production-weighted emission and level bands are the gate, no bond) and "is MCP still needed" (yes — it is a locked Phase 3 deliverable; the mod is additive).

12Appendix: what a mod is, verified API

A mod is a Claude Code plugin whose body is one register(on) file. It hooks about 35 engine events; at each it can let a call pass (next(e)), change it, or answer it. Anthropic ships four inside the binary and publishes their source at anthropics/claude-code/tree/main/mods. The built-in diff mod is the precedent for a live pane; agents-md is the precedent for injecting context.

VERIFIED against mods/types/claude-code.d.ts at anthropics/claude-code@main, read on 2026-09-20.
