The two-realm resource model

The organizing idea of the whole design. A single element type (say ERBIUM) exists in two forms that a player cannot freely move value between:

  • In-game realm — Balance<ERBIUM> held inside shared Planet stores and UniverseElementSource reservoirs. Produced by mines, consumed by construction, and moved planet-to-planet by the P2P and Compliance lanes. All internal Balance flow is unrestricted.
  • Wallet realm — Coin<ERBIUM> in a player's wallet. Reachable only by withdrawing from a planet store, and the withdraw is one-way: there is no function that turns a wallet Coin<ERBIUM> back into planet Balance. Its only use is to sell to The Company for NOVA.

"Withdraw-only" restricts the wallet boundary, not internal flow — but it is not enforced by "there is no deposit function." The red-team showed that claim is false: coin::into_balance<T> is a public Sui primitive, and any lane that accepts a caller-supplied element Coin/Balance and lands it on a planet reopens the door. The real invariant is a package-wide type-flow rule: no public function joins a caller-supplied element Coin/Balance into a planet store, reservoir, or escrow that later lands on a planet — with no exception at all (the Company is sell-only + burn, so there is no element re-entry). Trade and raid contributions must be pulled from the actor's own planet store via &mut Planet + PlanetCap, never passed as a Coin. Only Coin<NOVA> fuel crosses as a wallet coin (the Company being sell-only means there is no element re-entry to exploit). Enforced by review + a CI lint. See R2.

This model is what makes the earlier design tension evaporate. Element→NOVA pricing is transparent and on-chain; the in-game trade lanes carry real fuel-and-time cost; and DeepBook cannot cannibalise those lanes because a DeepBook-bought element can never re-enter a planet at all — its only use is to be sold to the Company and burned.

Tokens: elements & NOVA

Elements (ERBIUM, LANTHANUM, THORIUM)

  • Start with three Coin types but design for an expanding element list: more elements let tech demand different combinations — bigger ships one mix, faster ships another, cheaper/quicker construction another — so specialisation and trade deepen as the tree grows. Treat ERB/LAN/THO as the seed. 9 decimals; rescale every economy constant by 1e9 before any pool or wallet flow exists.
  • Global supply: one TreasuryCap<T> per element, held by the global shared ElementSource<T> (unchanged custody pattern).
  • Per-universe UniverseElementSource<T> reservoirs remain the production throttle, now refilled by a permissionless lazy drip instead of a manual keeper.
  • New player-facing bridge functions: withdraw_element<T>(planet, cap, source, amount) → Coin<T> (settles pending production first, one-way). No deposit_element for players.

NOVA

  • New nova module: OTW, coin::create_currency<NOVA>, 9 decimals, frozen metadata, plain Coin (not sui::token).
  • TreasuryCap<NOVA> is handed to company::found_company in the publish PTB and never leaves the shared Company. No admin mint entry exists.
  • Elastic supply, demand-gated: minted when a player sells an element to the Company (which recycles the element into the shared reserve pool, or burns it); burned by travel fuel and by mandatory non-fuel sinks — colonization, research, upkeep in element-value. Issuance is throttled at runtime by an exogenous demand signal — trailing net SUI inflow into the NOVA/SUI pool and pool depth — under one global per-epoch emission budget shared across all element markets. (Anchoring the cap to element production, as first sketched, is self-referential — the mint is the cap-raise — and wash-farmable; the revenue check flagged this.)
  • Lives in wallets as a normal coin; freely usable to fuel any planet's operations (matches "rich players accelerate"). Real-money value comes from exogenous SUI buy-in, defended by production-weighted emission (a fresh planet mints little) plus the mandatory non-fuel sinks, not from the fuel sink; the cash-out cut is revenue and anti-wash — see the Sybil stance.

The fuel sink does not anchor NOVA's value — design accordingly. Fuel is bought with NOVA a player already earned, and the pure value-extraction loop drip→extract→sell→NOVA→SUI burns zero fuel, so the fuel sink can't stop mine-dump-cash from printing money. NOVA's value comes from exogenous buy-in (players paying SUI to accelerate). Defend it by weighting each planet's emission share by planet age + cumulative production (decided 2026-09-20: a farm of fresh planets mints a sliver and dilutes itself against one bounded budget) plus structural NOVA demand from the mandatory non-fuel sinks (colony/research/upkeep in element-value). The element→NOVA price is a mean-reverting EMA controller, not constant-product — see the Company section and the sell-only conditions.

The Company

The NOVA issuer, per-element price controller, and rate oracle. It is sell-only: players sell elements to it for freshly-minted NOVA, and it recycles (or burns) every element it receives. There is no buy_element — elements never re-enter a planet from the Company.

public struct ElementMarket<phantom T> has key {   // one per element — shards write-contention (R7)
    id: UID,
    price_e9: u64,          // current EMA price, NOVA per element (1e9-scaled)
    last_update_ms: u64,    // for time-based mean-reversion (the re-arm)
    net_sold: u128,         // cumulative net-sold-and-burned — decays the re-arm ceiling
    // constants: P0 anchor, P_min oracle floor, depth_L, lambda (re-arm rate), alpha_cap (<=5%/update)
    // per-planet per-epoch mint quota, weighted by planet age + cumulative production
}
// NOVA TreasuryCap lives in a shared Company object; minting is the only privileged op.
// Purchased elements are BURNED via ElementSource::decrease_supply (batched furnace) — no vault.

Element → NOVA (sell) — the only Company interaction

sell_from_store<T>(market, planet, cap, amount, min_nova_out) → Coin<NOVA>, atomic from the planet store (folding in the withdraw so a wallet round-trip is never needed). The controller re-arms the price toward the anchor by the elapsed-time factor, pays mint = P·L·ln(1 + Δe/L) from the unfloored payout price (a floor on the payout would re-open sybil faucet inflation), pushes the price down, mints NOVA under the per-planet quota (weighted by planet age + cumulative production, so identity does not matter), and burns the element. Emission self-caps at F_max = P0·λL per element, scaling with gated universe count — this soft ceiling replaces the old epoch_mint_cap hard-abort (R9).

Emission weight per planet — starting shape (2026-09-20, playtest number)

The per-planet quota that replaces the per-account one. Its job is to make a fresh planet worth almost nothing to a farm while a real player never notices it. Two linear ramps, multiplied:

age_w  = min(1, planet_age_ms / T_AGE)              // T_AGE  ≈ the newbie-immunity window (14 d to start)
prod_w = min(1, cumulative_production / P_REF)       // P_REF  ≈ what one L3 mine produces in T_AGE
w      = age_w × prod_w                              // 0 → 1 over the first weeks

quota_e(planet) = EPOCH_BUDGET × (w × prod_e) / Σ_sellers (w × prod_e)   // share of this epoch's demand-gated budget
  • Why two ramps. Age alone is beaten by pre-minting planets and parking them; production alone is beaten by a burst of drip on day one. Together, a planet must exist and have mined for weeks — and mining draws on the same bounded drip real players use, so a farm dilutes itself against the drip before it ever reaches the NOVA budget.
  • Why a product, not a minimum. min() would let a one-week-old planet with a burst of production sell at 50%; the product keeps early weight near zero (at one week: 0.5 × ~0.3 ≈ 0.15) and rises steeply in weeks two and three, which is where legitimate players arrive.
  • Quota is a share, not a cap. The budget is fixed by demand; weights only decide who gets it. N fresh planets with w≈0.1 take 10% of what one mature planet takes from the same pool — sybils compete with each other, not with the ceiling.
  • No banking. Unused quota lapses with the epoch (lazy reset, as R9). Otherwise a farm sits idle to accumulate.
  • Colonies inherit nothing. A new colony starts at w=0 like any planet. That is intended: colonization is paid for in NOVA and pays back in elements first, NOVA later.
  • The check (revenue condition 5): simulate N fresh planets over T_AGE against a mature baseline and confirm total NOVA minted < gas spent. If it fails, lengthen T_AGE or steepen with an exponent on prod_w before touching anything else.

Knobs: T_AGE, P_REF, and an optional exponent on prod_w. Both inputs already exist on-chain: planet creation timestamp and the mine accounting fields.

Rate oracle (hardened)

company_rate<D, P>(markets, clock) → (num, den) derives the Compliance cross-rate from a floored oracle price (max(P_min, P_eq)) over a long TWAP — never the raw sell price, because sell-only pricing makes a hoarded element read as cheap exactly when it is scarce (oracle inversion). It requires a minimum number of distinct recent sellers, caps any one account's contribution per window, and blends in Lane B P2P clearing prices and a real-scarcity term (reservoir level / recent net drip−burn). The rate is snapshotted at raid launch, never read live at settlement.

Sell-only + burn adoption conditions (economics check verdict: adopt-with-conditions). The price is an EMA-price + depth controller, not constant-product (raw CP with no buy side ratchets to zero). Floor the oracle, never the payout. Publish F_max and verify total emission against DeepBook NOVA/SUI depth. The re-arm ceiling decays with cumulative net-sold volume so batch-dump-and-wait can't farm it. And — crucially — the fuel sink does not anchor NOVA's value, so NOVA is defended by production-weighted emission plus the mandatory non-fuel sinks; the cash-out cut is revenue.

How the game earns (revenue)

The game captures value from NOVA, never from elements. Seigniorage: the Company mints a small configurable cut of every NOVA issuance into a treasury Balance<NOVA>, realizable as SUI via the NOVA/SUI pool as play and pay-to-accelerate demand grow — the monopoly edge. Fees to treasury: the NOVA fee for registering a commander in further universes, the NOVA→SUI cash-out cut, and private-universe creation (influencer-hosted universes and events). The element→NOVA controller stays unrigged — the game never profits by manipulating element valuations. Element disposal is a supply-tuning choice, not a revenue one: recycle to a global reserve pool (decided 2026-09-20 — offsets fresh drip, destroys nothing, and re-enters the shared drip rather than a chosen planet so it reopens no buy-side bug) or burn for harder scarcity. Recycled feedstock must never re-mint NOVA or re-increment any emission counter, and must be priced ≥ its NOVA sale value to kill buy-back wash loops.

Revenue-model conditions (check verdict: sound-with-conditions — a legitimate seigniorage+fees business, not a Ponzi; the real risk is GameFi inflation-collapse, not fraud). Close before Phase 2: (1) gate NOVA issuance on a runtime exogenous-demand signal, not element production or a publish-time constant; (2) one global emission budget across all element markets (per-element caps let diversification inflate the aggregate, and a growing element list inflates it further); (3) price private-universe creation ≥ the seigniorage value of the emission headroom it unlocks, and decide whether a private universe shares or isolates the budget; (4) make treasury NOVA→SUI selling adaptive — throttle below a price/inflow floor so the Company sells into strength, never compounding an inflation dip; (5) (superseded 2026-09-20) weight each planet's emission share by age + cumulative production and verify in simulation that a farm of N fresh planets earns less than its gas over the immunity window — the bond is dropped and the cash-out cut is no longer asked to be the gate; (6) produce a quantitative sustainability model (break-even paying fraction on a pessimistic low-spend playerbase) before committing.

The trade lanes

AElement → NOVA at the Company

Not a module of its own — it is sell_from_store above. Serves element→NOVA price discovery and cash-out. Sell-only: there is no buy side and no re-entry; the element sold is burned.

BP2P in-game element trade — the core mechanic

New trade_port module. Each offer is its own shared object; goods move as Balance and never touch wallets.

public struct TradeOffer<phantom O, phantom W> has key {
    id: UID, universe: ID, seller_planet: ID, origin: PlanetInfo,
    offered: Balance<O>, want_amount: u64, expiry_ms: u64,
}
  • create_offer — seller escrows offered withdrawn from their planet store (production settled first). No NOVA cost to list.
  • accept_offer — level-band check between buyer and seller; buyer supplies the wanted element (from their store) + fuel: Coin<NOVA> ≥ round-trip fuel for the distance; fuel is burned; two Shipment objects are created that arrive after Δt = distance · ms_per_distance.
  • claim_shipment — after arrival, deposits the cargo Balance into the destination planet (permissionless credit; cargo can only land on its addressed planet).
  • cancel_offer / permissionless sweep_expired — return escrow, bound shared-object litter.

CCompliance raid — enforced trade

New compliance module. A public function on the target's shared Planet that performs a cap-less mutation gated purely by economics. Two phases; the cross-rate is snapshotted at launch (never read live at settlement, which both sides could otherwise author by trading the curve). This lane is also the anti-corner mechanism: because settlement reaches pending output, no cartel can strangle an element's supply.

  • launch<D, P> — burns fuel immediately (the NOVA at risk, wasted on a miss), snapshots company_rate into the fleet, escrows the attacker's payment pulled from the attacker's own planet store (never a wallet coin), creates a shared ComplianceFleet with arrival_ms, and emits a visible event so the target sees it coming.
  • execute<D, P> — after arrival, settles at the launch-snapshot rate (±~5% clamp) against (on-hand + the target's own outstanding offer escrows + inbound shipments + a slice of pending mine output), so parking stock elsewhere cannot dodge. Target is paid at the defender-favorable rate; a miss returns the escrow and the launch fuel stays burned.
  • Guards (sybil-invariant): the level-band rule (attacker and target within the interaction band), newbie-immunity keyed to planet age + cumulative production (not overseer freshness), a global per-target incoming-raid rate limit and min re-launch interval counting all attackers, and a max-fraction-per-landing cap. Every planet can always receive shipments with no local infrastructure — that plus this settlement basis is the hard-zero colony bootstrap.

DNOVA / SUI on DeepBook — the P2E layer

One permissionless Pool<NOVA, SUI> (optionally NOVA/USDC). Created once (500 DEEP), then organic two-sided liquidity keeps it alive; the game runs no market maker here. All game swaps pass coin::zero<DEEP>() (input-token fee, no DEEP). This is where NOVA earns real-money value and where whales buy in.

Production & progression

Mining & cost curve

  • Keep lazy accrual; store accrual in milli-units and carry the remainder so frequent extracts never truncate to zero.
  • Cost = base · (3/2)^L (u128 pow, capped MAX_LEVEL), replacing linear — this creates the big late-game lumps that make stockpiles raid-exposed.
  • Asymmetric cost matrices (an ERB mine costs mostly LAN+THO) so specialise-and-trade beats self-sufficiency even under soft scarcity.
  • Richness multiplier per element, rolled at claim; first planet all three, colonies may roll a hard zero.

Storage — halt at cap

  • effective = min(produced, capacity − stored); a full store halts that mine. This single clamp also retires the mine-bricking bug.
  • Storage depots are a build option; capacity vs upgrade-lump sizing is the dial that sets raid exposure windows.

Build slots & lazy queue

  • Each building level consumes a planet field: mines, storage, shipyard, lab, terraformer, nova-beacon.
  • start_build pays now; claim_build after ready_at (Clock). Time-gates progression independent of raw wealth, and needs no keeper.

Ships, research, colonies

  • Ships = trade capacity, shipyard-gated, planet-bound for v1 (Kiosk-tradable NFTs deferred). Largest element sink → route to burn.
  • Research per-overseer-per-universe (TechSet on Overseer keyed by universe): extraction, cargo, astrophysics, nova-efficiency, compliance-shield. One lazy order at a time.
  • Colonization: choose free coordinates; cost = colony-ship + NOVA fee ∝ distance · 2^colony_count; hard cap 1 + astrophysics_level; abandon_planet returns coords so universes never exhaust.

Sinks & emission

  • Mine + storage upgrades recycle to the universe reservoir (keeps it solvent, drip stays small). Ships, research, terraformer burn (net element deflation).
  • Emission is a permissionless lazy drip: any player whose extraction would fall short prepends a drip_refill in their PTB. No cron, no admin keeper. Net inflation = drip − burn, both event-observable.

Optional mechanic worth prototyping: Supply Contracts. A planet posts a standing on-chain order (element X for Y at ratio R, escrowed); others fill it by shipping (NOVA burn). It is the demand generator that makes hard-zero colonies viable, and it gives the Compliance raid a clean definition — "forcibly filling an unposted contract at the Company cross-rate, skewed to the defender."

Distance & fuel

Implementing calculate_travel_distance (today a stub returning 0) is now load-bearing — it feeds trade fuel, raid fuel, and colony fees. Use an OGame-style metric over the existing (galaxy, system, position) coordinates:

distance =
   different galaxy  -> 20_000 * |g1 - g2|
   same galaxy       ->  2_700 + 95 * |s1 - s2|
   same system       ->  1_000 +  5 * |p1 - p2|
   same slot         ->      5

round_trip_fuel = fuel_base + 2 * distance * fuel_per_distance   // buyer pays full round trip
travel_time_ms  = distance * ms_per_distance

Research (cargo / nova-efficiency) scales the effective rates per player; fleets snapshot the effective rate at launch.

Agentic-readiness layer

The on-chain prerequisites so the future CLI + MCP agents can enumerate, plan, monitor, and act atomically. None of the CLI/MCP itself lives here — only what the contracts must expose.

  • Events per state transition — join, mine upgrade, harvest, refill, trade lifecycle, raid lifecycle, colony — each carrying universe ID + timestamp. Replaces object diff-polling; makes the game indexable.
  • Snapshot views — one snapshot(&Planet, &Clock) → PlanetSnapshot (copy+drop) replacing today's 15-call read pattern; same for Universe and Overseer empire.
  • Preflight quotes — abort-free upgrade_quote etc. that check both affordability and source coverage, closing the simulate-vs-execute gap.
  • Idempotency guards — expected_level on mutating calls; clamp + remainder-carry on extract so any schedule is safe and retries never double-spend.
  • Composability — player mutators become public fun returning small receipts (keep join_universe a private entry for &Random), so strategy PTBs chain harvest → withdraw → sell → fuel → upgrade.
  • Discoverability — occupation events + a coordinate→planet index (occupied: Table<u32, ID>, planet_at(coords)), needed for raid targeting and for agents to build the universe map; also retires the 255³ eager-materialization gas blowup.
  • Error hygiene — Move 2024 #[error] strings, unique code ranges, membership pre-checks so no framework abort leaks to an agent.

Red-team hardening

An adversarial review (6 attackers + a synthesis critic) stress-tested this design. Verdict: the two-realm framing and the phasing are sound, but four load-bearing ledger claims were false as first written and the NOVA controller and Lane C credibility were unresolved. Every finding is a Phase 2 (market) concern — none touch Phase 0, whose modules do not yet exist — so Phase 0 is green-lit now and Phase 2 is gated on the items below. The corrections above (ledger, two-realm, NOVA, Company) already reflect this; the required design changes are catalogued here.

Phase 2 is blocked until these four are resolved in the spec: (1) the withdraw-only type-flow invariant [R2]; (2) the compliance rate snapshotted at launch [R1]; (3) the NOVA feedback controller [R3]; (4) Lane C credibility — settlement basis, premium recipient, and sybil-invariant guards [R4].

Critical & high findings, with fixes

R1critCompliance rate is authorable by whoever moves the curve last. execute reads the EMA at arrival and is permissionless, while sell/buy update that same EMA — so an attacker (or defender) trades the curve and settles at their own rate in one PTB; safety_margin is the exact width a defender can extract. Fix: snapshot company_rate into the ComplianceFleet at launch, settle at rate_launch (clamp arrival drift to ±~5%); execute then checks only physical store availability. Fix: route fuel into a Balance<NOVA> furnace, batch-burn once per epoch (cap touched once); shard the market per element (ElementMarket<T>); all rate/quote/snapshot reads take &Company (immutable).
R8highOverseer gating cannot create identity scarcity. One-per-address = one-per-keypair = unlimited; no SUI fee stops farming without killing f2p P2E — so every per-overseer rule (one-planet, colony 2^count, newbie-immunity, cooldowns, per-universe research reset) leaks. Fix: move scarcity off the identity axis — price expensive actions in SUI scaled to total account activity; tie immunity/cooldowns to planet age + cumulative production, not overseer freshness; monotonic per-account colony counter that abandon never decrements. Adopted 2026-09-20: bond dropped; see the Sybil stance below.
R9addressedepoch_mint_cap hard abort — REPLACED by the sell-only controller's F_max = P0·λL soft ceiling (payout steepens near the cap, net accounting, never gates fuel, lazy epoch reset). (Original risk: a whale exhausts a global hard cap to deny cash-out + fuel for every universe.)
R10highEphemeral objects lack single-consumption; recycle can underflow drip. A double claim_shipment mints Balance from nothing; over-recycling past max_reserves underflows max_reserves − reserves and bricks emission. Fix: consume-once via an Open→Accepted/Cancelled/Swept state enum, delete-and-take-by-value; saturating drip math; cap return_reserves and route excess to burn; tests for double-claim / accept-then-sweep / over-recycle.
R11highcolonize needs &Random, so it cannot be a composable public fun and is grind-retryable. Fix: package-private entry that applies the roll atomically with no caller-branchable return; list it beside join_universe in the non-composable carve-out.
R12medGeometric cost overflows and soft-locks with storage. base·(3/2)^L overflows the intermediate ~L60 and exceeds u64 ~L53; and if storage cap < the upgrade lump the lump can never be assembled. Fix: fold /2 into the pow; assert MAX_LEVEL (clean game error) below min(u64 domain, max_reserves, storage capacity); hard constraint storage capacity ≥ max upgrade lump.
R13medNOVA/SUI is empty at cold start under "no market maker" — mid_price aborts EEmptyOrderbook and the P2E promise is unmet at launch; DeepBook is also externally version-gated. Fix: bootstrap protocol-owned launch liquidity as an explicit exception to "no MM" (or gate P2E messaging until organic depth); isolate DeepBook behind an upgradable adapter; never call mid_price unguarded, anchor on the Company EMA.
R14medEphemeral shared objects are never reclaimed — offers, shipments, fleets, and closed-universe reservoirs accumulate forever, slowing readers. Fix: auto-delete at each terminal transition (rebate to caller); sweep bounty > gas; a universe teardown that frees reservoirs + the coordinate index.

Open design questions

Adopting sell-only + burn with the pure-market anti-corner route resolved most of these; one remains.

  • Why raid at all? — resolved. Removing buy_element deletes raiding's only competitor; mining, Lane B, and raids are now the sole ways to obtain a non-mined element, so Lane C has a clear niche.
  • Hard-zero colony bootstrap — resolved. A colony receives its first X via its own empire's shipment (free receive, no local infra) or a raid; settlement reaching pending output guarantees X is always obtainable from any miner.
  • Compliance premium recipient — resolved. The premium is a price skew in the defender's favor (a BATNA, not a routed fee); self / same-overseer raids are forbidden (R2) so it cannot be recycled for free.
  • Sybil stance — decided 2026-09-20, no bond. Creating a commander is free and the first universe is free. Registering the same commander in each further universe costs NOVA: a progression tax and a structural sink, routed through the market you want deep; not the anti-farm gate, since a sybil mints another free commander instead of paying. The gate is dilution: each planet's share of the demand-gated emission budget is weighted by planet age + cumulative production (the basis raid immunity and cooldowns already use), so a fresh farm planet mints a sliver for weeks and farms compete with each other for one bounded budget. The drip already makes total supply sybil-invariant, so sybil harm is distributional and dilution answers it directly. A level-band interaction rule (commanders far apart in progression cannot trade with or raid each other) blocks alt-boosting and bullying with one rule. The cash-out cut stays as revenue and anti-wash cost; it is no longer asked to make farming unprofitable, which a percentage cannot do. Rejected: trade-price floors (break legitimate forward trades). Deferred to Phase 3+: community-defined trade contracts on the composable public API. Playtest numbers: the age/production weighting curve, the per-universe NOVA fee, the level-band width.

Build sequencing

  1. Phase 0 — Harden. The fixes + invariants + tests above. Ends at a correct, tested version of today's slice.
  2. Phase 1 — Foundations. Coin withdraw bridge + harvest; event/snapshot/preflight/idempotency layer; composable public fun; lazy drip; storage caps. Ends with an agent-drivable production game.
  3. Phase 2 — Market. nova + company (curve live day one); trade_port (Lane B); compliance (Lane C) with guards; NOVA/SUI pool (Lane D). Ends with the full trade economy. Gated: do not start until the four Red-team hardening blockers (withdraw-only invariant, launch-snapshot rate, NOVA controller, Lane C credibility) are resolved in the spec.
  4. Phase 3 — Full game. Planet differentiation, build slots, ships, research, colonization; optional Supply Contracts. Then the CLI (fresh in TypeScript) and the MCP server on the now-ready API.

The order is dictated by dependencies, not preference. Every market and agent mechanic needs the coin bridge + event layer (Phase 1); those need the invariants + tests (Phase 0). Building NOVA before the exploit chain is closed ships a money printer; building the CLI/MCP before the API is agent-ready means rewriting both against a moving contract.

Tuning knobs (set during the build / at playtest)

Architecture-neutral numbers. Wrong values change feel, not structure — settle them with simulation and playtest, and expose the sensitive ones behind GameAdminCap.

  • Cost-curve growth (~1.5×) and MAX_LEVEL; asymmetric cost matrices per element.
  • Richness spread and hard-zero probability for colonies.
  • Storage capacity vs upgrade-lump ratio (sets raid exposure).
  • Fuel: fuel_base, fuel_per_distance, ms_per_distance; distance metric constants.
  • NOVA controller: anchor P0, floor P_min, depth L, re-arm λ, per-update cap α, per-planet age/production-weighted mint quota, and F_max checked against DeepBook depth; the cash-out cut (revenue); premium_bps; the faucet/sink balance (highest-risk).
  • Drip rate + max reserves; recycle-vs-burn split.
  • Colony NOVA fee curve; astrophysics colony cap; abandon cooldown.
  • Raid newbie-immunity window + per-target cooldown.
  • Emission weight: T_AGE, P_REF, optional exponent on prod_w (see the Company section).
  • Further-universe registration fee in NOVA; level-band width for trade/raid interaction.
  • DEEP sourcing + target network for the NOVA/SUI pool; whether to add NOVA/USDC.
  • Deferred: ships as Kiosk-tradable NFTs; additional element types.
